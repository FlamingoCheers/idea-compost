## 2. LLMClient 接口

```kotlin
interface LLMClient {
  suspend fun complete(req: CompletionRequest): CompletionResult
}

data class CompletionRequest(
  val system: String,          // capability_card / gardener_system + 阶段调度指令
  val user: String,            // 上下文包（+ 前轮输出）
  val purpose: String,         // 日记归因：identify|convoke|ferment_r2|integrate|assess|distill|title
  val compostId: String?,      // null=场外调用（夜间/标题）
  val maxTokens: Int = 4096,
  val temperature: Float? = null   // null=用 profile 默认；评估类（S5）固定 0.2
)

sealed interface CompletionResult {
  data class Ok(val text: String, val usage: Usage) : CompletionResult
  data class BudgetExceeded(val spent: Int, val cap: Int) : CompletionResult
  data class Failed(val error: CallError, val retried: Int) : CompletionResult
}
```

### 传输层（OkHttp + Retrofit）

```text
POST {baseUrl}/chat/completions      OpenAI 兼容体
  {model, messages:[{role:system},{role:user}], temperature, max_tokens}
超时    connect 15s / read 120s（Agent 长输出，无流式，整段返回）
重试    5xx 与网络错误：指数退避 2s/8s/32s ×3；4xx（鉴权/参数）不重试直接 Failed
鉴权    Authorization: Bearer {apiKey}，拦截器统一注入；日志拦截器脱敏 body 只记长度
```

> 不传 `response_format: json_object`——兼容性参差。JSON 纪律由客户端管线保证（§4）。

## 3. 预算守卫（08 §5 落地）

```kotlin
class BudgetGuard(private val cap: Int = 20) {   // 单场堆肥 ≤20 次调用
  fun tryAcquire(compostId: String): Boolean     // 查 llm_calls 实计数，超限拒发
  fun onCut(compostId: String)                   // 熔断标记 status=budget_cut
}
```

熔断语义（03 §2 标准模式 ≈20 次上限）：发酵轮未完成但预算耗尽 → **跳过剩余轮次直接进整合**（integrate 必须保留预算：调用前预留 2 个名额——integrate + assess 各一）。

## 4. JSON 可靠性管线（核心）

Agent 输出契约是严格 JSON（03 §6.2），但模型会吐围栏/前后缀。五级管线：

```text
① 剥壳    去除 ```json 围栏、定位首个 { 到配对 } 的最大跨度
② 解析    kotlinx.serialization → 数据类（schema 不符 = 解析失败）
③ 语义校验  a. claim.id 前缀 = 该 Agent 短码，编号不重复
           b. citations 白名单：idea:N / insight:N / claim:{本场已存在的 id}
           c. confidence ∈ 三档枚举
④ 修复调用  ②/③ 失败 → 一次修复调用：system 原文 + 出错 JSON + 错误清单
           （"只返回修正后的 JSON，不要解释"），修复也计预算
⑤ 降级    修复仍败 → 该 Agent 该轮输出标记 degraded：
           - 发酵轮：丢弃该 Agent 本轮输出，compost_stages.status=degraded，菌群继续
           - 整合轮：整体 failed → 挂起，等用户重试（stage 粒度，INV-8）
           - 评估轮：跳过营养评分（本场 nutrition_awarded={}，不阻塞产物交付）
```

校验失败率是模型选型指标：设置页展示「结构化输出成功率」（llm_calls 里 repaired/ok 比值）。

## 6. 调用纪律汇总（与 03 协议对齐）

| 场景 | 纪律 |
| --- | --- |
| 发酵轮内单菌失败 | 该菌标 degraded，同轮他菌继续（不重试整轮） |
| stage 失败 ×3 重试仍败 | 挂起该 stage，compost.status=suspended，保留 7 天 |
| 切后台/锁屏 | 当前调用自然完成后暂停（不 kill），回前台从最近 stage 续跑（08 §7.1） |
| 夜间蒸馏（T2/T3） | 独立 WorkManager 队列，purpose=distill，compostId=null，充电+WiFi 约束 |
| 标题懒生成 | purpose=title，maxTokens=48，失败静默（INV-3 不阻塞保存） |
| 台账 | 每次调用（含失败/修复）写 llm_calls；cost 聚合进 composts.cost |

## 7. 错误分类（CallError）

```text
Network        IO/超时——可重试
Server5xx      可重试（退避）
Auth           401/403——不重试，提示检查 Key
Quota          429/余额——不重试，熔断本场并提示
BadSchema      修复调用后仍失败——按 §4⑤ 降级
ContextTooLong 413/400(上下文)——预检拦截（03 §3 ≤24K 原则上不会触发，触发即 bug）
```

## 8. 安全边界重申

```text
唯一出网流量 = 用户配置的 AI API 的 prompt 与返回（OkHttp 单 base url 白名单）
面包渣/产物/菌床/反馈 永不出设备；导出走用户主动 .md/.png
Key 存 EncryptedSharedPreferences（AndroidKeyStore 加密），无云备份标志 android:allowBackup=false
崩溃日志（若开）剥离全部内容字段，只留 purpose/status/latency
```
