# 03 · 思想园丁调度协议 / Gardener Protocol

> v0.2 设计文档集 · 对应 v0.1「下一阶段设计重点」第 3 项
>
> 定义：园丁如何阅读菌床、分析面包渣、选择 Agent、安排多阶段讨论、判断停止时机、产生堆肥产物、更新菌床。

------

# 1. 园丁的身份

> **你是一名思想园丁。** 不是秘书，不是搜索助手，不是总结器，不是写作助手。
>
> 你是一个帮助用户长期培育思想的认知生态管理者。

核心任务（v0.1 §36 落实）：理解思想而非整理文字；发现连接而非简单总结；质疑前提而非无条件认同；保留不确定性而非制造虚假确定性；提出新的可能而非替用户决定结论；管理菌群而非包办全部推理；让每次堆肥反哺菌床。

禁止清单（写入系统 Prompt）：

```text
- 不替用户下最终结论（产物用「正在形成的判断」，不用「结论」）
- 不使用奉承性开头（"这是个很好的问题！"禁止）
- 不消除矛盾（矛盾显式保留为 🔥 节）
- 不把菌床摘要当作用户当前意愿（INV-11：菌床=历史生态，益生菌=本次意志）
- 不在缺少证据时给出高置信度标注
```

------

# 2. 全流程总览

```text
阶段 0  预检 Preflight        （纯代码，0 次 LLM）
阶段 1  识别 Identify         （园丁，1 次调用）
阶段 2  召集 Convoke          （代码强制配额 + 园丁微调，1 次调用）
阶段 3  发酵 Ferment          （菌群，2-4 轮 × K Agent）
阶段 4  整合 Integrate        （园丁，1 次调用）
阶段 5  评估反哺 Assess       （园丁 1 次 + 代码落库）
```

每阶段产物即 checkpoint（INV-8：失败从最近阶段恢复，不整场重跑）。

LLM 调用预算：标准模式 ≈ 1+1+(3轮×5菌)+1+1 = 20 次上限；浅模式 ≈ 8 次。

------

# 3. 阶段 0：预检（纯代码）

```text
输入：selected_ideas[], probiotics[]
1. 面包渣文本合计 ≤ 24K token；超出 → 拒绝并提示精选
   （不静默截断——截断=丢失思想；图片走描述通道只计描述 token）
2. 益生菌 ≤ 2 个
3. 深度选择：浅(2轮)/标准(3轮)/深(4轮)，默认按面包渣数量推荐
4. 组装上下文包，创建 compost 记录（status=pending）
```

**上下文包**（园丁与菌群共同看到的世界，≈30K token）：

```text
本次面包渣全文（永不压缩，INV-1）           ≤24K
益生菌卡（prompt_logic+参数）               ≤1K
菌床快照 bed_summary（T3 全局摘要）         ~1K
相关休眠菌压缩卡（embedding top-5）         ~1K
高相关既有洞察（top-10，含置信度与状态）     ~2K
活跃菌索引（≤24 个名字+一句话能力）         ≤1K
```

> 面包渣原文永远完整进入上下文。ACP 式压缩只用于历史产物（见 06），绝不用于本次输入——发酵原料不能是「原料的摘要」。

------

# 4. 阶段 1：识别（园丁调用 1）

任务：理解这批面包渣在「想什么」，不评判、不整理。输出严格 JSON：

```json
{
  "gist": "这批碎片共同指向的问题（1-2 句）",
  "potential_domains": ["算法推荐", "媒介研究"],
  "potential_methods": ["概念辨析", "反事实"],
  "tensions": ["碎片A与碎片C在 X 上存在未言明的张力"],
  "premises": ["碎片B隐含假设了 Y，但 Y 未被检验"],
  "bed_links": [123, 456],
  "suggest_depth": "standard"
}
```

`tensions` 与 `premises` 是本阶段最重要产物——阶段 3 冲突轮与魔鬼代言人以此为弹药。

------

# 5. 阶段 2：召集（代码为主，园丁微调）

```text
1. 代码按 02 协议 §4 计算 w(a)，强制 70/20/10 配额
   + 反驳菌保证 + ε-greedy
2. 园丁一次轻调用：可否决/替换至多 1 个意外菌，需给理由
   （理由入 gardener_plan；意外菌否决率过高 = 回声风险信号，
    计入生态健康审计）
3. 产出 4-7 个 Agent：激活权重 + 配额角色
```

> 召集主体是**代码不是 LLM**（02 D11 执行点）：园丁可建议，配额底线由代码守护。

# 6. 阶段 3：发酵

## 6.1 v0.1 七阶段 → 三轮实现（成本/深度折中）

```text
轮 1 · 理解拆解（v0.1 阶段1+2）
  全部召集菌并行，各看：上下文包 + 自己的 capability_card
  输出：各自视角的核心问题、关键概念、隐含前提

轮 2 · 连接冲突（v0.1 阶段3+4+5）
  全部参与且互看轮 1 输出（交叉）
  方法菌主导：反驳菌对轮 1 最强主张构建反驳
  领域菌主导：寻找轮 1 未连接的跨域结构
  输出：连接候选、冲突清单、跨学科重组

轮 3 · 新假设（v0.1 阶段6）
  创造菌 + 权重最高的 2 个领域菌；输入轮 1+2 全部
  输出：新假设/新概念/研究问题候选（命题化+置信度）
```

```text
浅 = 轮1+轮3（1-2 个面包渣快发酵）
标准 = 3 轮
深 = 3 轮 + 轮 2 拆「连接」「冲突」两轮 + 独立魔鬼代言人轮
```

## 6.2 单 Agent 调用契约

```text
system = capability_card + 调度指令（角色、阶段目标、输出 schema）
user   = 上下文包（同轮统一，保证可交叉）+ 前轮输出（轮2起）

每 Agent 输出 schema：
{
  "agent": "社会学菌",
  "stage_outputs": { "...": "阶段特定字段" },
  "claims": [ {"id": "S1", "text": "...", "confidence": "中"} ],
  "citations": ["idea:3", "insight:12", "claim:R2"]
}
```

claims 逐条带 ID 是营养评估（引用证据）与产物溯源（🍞/🧠 节）的基础。禁止 Agent 引用不存在的 ID（幻觉溯源=硬错误，校验后整段丢弃并记质检指标）。

# 7. 停止条件（何时结束发酵）

满足任一即提前收敛，跳到阶段 4：

```text
① 连续一轮无新增 claims、无新增 citations（信息饱和）
② 轮 2 冲突清单在轮 3 后全部被回应且无新冲突（收敛）
③ 轮次预算用尽（硬上限 4 轮）
④ 检测到复读（本轮输出与上轮 embedding 相似度 > 0.9）
```

> 发酵的价值在增量。宁可提前收敛进入整合，不为流程完整而空转烧钱。

------

# 8. 阶段 4：整合（园丁调用，v0.1 阶段7）

园丁只整合**不新增观点**。输入：上下文包 + 全部轮次输出 + tensions/premises。

输出 = 05 输出协议定义的 `compost_output` JSON（十节结构），含：
- 从各 Agent claims 中挑选、组织（保留矛盾与不确定性）
- 逐条命题标注 source_claims（溯源）
- 最强反方观点必须构建（无反驳菌参与时由园丁以「魔鬼代言人」身份补足——强制条款）
- 无 high 置信度可用时，标题与判断必须用「初步/可能/待检验」措辞

------

# 9. 阶段 5：评估与反哺（园丁 1 次 + 代码）

```text
1. 园丁按 02 协议 §3 评估各 Agent 营养（需引用证据）
2. 代码落库事务：
   a. output_note 保存（JSON 真源 + 渲染 MD，D5）
   b. adopted 候选洞察入库（status=emerging，待用户反馈转正）
   c. nutrition_awarded 累加，营养缓冲更新
   d. bed_event 追加：compost_completed {agents, insights, probiotics}
   e. 物化快照刷新（如触发）+ embedding 入库
3. status=awaiting_feedback → 用户阅读/反馈 → status=completed
4. 延迟营养事件（❤️⭐↗/修改/引用）在事件到达时结算
```

------

# 10. 失败恢复语义（INV-8）

```text
阶段0-2 失败 → compost=failed，可整场重启（成本可控）
阶段3 某轮失败 → 仅重跑该轮（同轮 Agent 幂等，输入为已存 stage 产物）
阶段4 失败 → 重试整合（输入已齐）
阶段5 失败 → 落库重试队列（幂等：bed_event 按 compost_id 去重）
用户中途退出 → status=suspended，保留 7 天可续跑（从最近 stage 恢复）
```

# 11. 本文关键决策汇总

| # | 决策 | 理由 |
| --- | --- | --- |
| D17 | 五阶段流水线，每阶段产物即 checkpoint | 崩溃恢复 + 可审计回放 |
| D18 | 面包渣原文永不全量压缩后输入 | 发酵原料不能是摘要 |
| D19 | 七思考阶段折叠为三轮调用（深/浅模式展开） | 成本与深度折中 |
| D20 | 召集配额代码强制，园丁只能微调 | 茧房防线算法性（02 D11 执行点） |
| D21 | Agent 输出逐条 claim 带 ID + 引用校验 | 溯源与营养评估的原子单位 |
| D22 | 信息饱和即停，硬上限 4 轮 | 增量价值递减 |
| D23 | 园丁整合期只组织不新增 | 园丁是生态管理者非答案机器 |
| D24 | 无反驳菌时园丁强制补位魔鬼代言人 | 产物必须含最强反方（v0.1 §29） |
| D25 | 用户反馈前洞察为 emerging 态 | 用户是采纳的最终裁判（P-03） |
