# 02 · Agent 生态协议 / Agent Ecology Protocol

> v0.2 设计文档集 · 对应 v0.1「下一阶段设计重点」第 2 项
>
> 本文定义：Agent 如何激活、如何获得营养、Vitality 如何计算、如何增殖、如何融合、如何压缩、如何休眠、如何唤醒。
>
> 生态协议是本产品区别于普通 Agent Cluster 的核心设计（v0.1 §17），也是全部自研逻辑所在——没有任何现成框架提供这套机制（见 07 框架调研）。

# 1. 初始菌群（Seed Colony · 首启自选）

**首次打开 APP：用户点选一级菌域，共 7 个选项，可多选（1-7 个）。**

一级菌域是**通用学科领域**（v0.1 §16.1 的领域菌谱系，非任何用户个性化示例）：

```text
哲学菌   技术菌   心理学菌   经济学菌
历史菌   科学菌   文学菌
```

> v0.2.2（视觉稿 v1.1 评审反馈）：首启菌域由「哲学/社会学/心理学/经济学/历史/认知科学/文学」调整为「哲学/技术/心理学/经济学/历史/科学/文学」；社会学、认知科学移出首启，改由 §5 增殖机制生成（见下 ④）。

初始菌群组成：

```text
① 用户选中的一级菌域（1-7 个）    status=active，  V = 50
② 通用底座：方法菌（6）+ 创造菌（4）
   反驳菌 反事实菌 概念辨析菌 因果机制菌 类比菌 证据审查菌
   假说菌 研究问题菌 隐喻菌 概念生成菌
                                  status=active，  V = 40
   （过程性能力，人人通用，无需选择）
③ 未被选中的菌域（0-6 个）        status=dormant（压缩卡，含唤醒暗号，
                                  按 §7.3 随时可被唤醒）
④ 社会学/认知科学/媒介研究等其他领域  不预置，由 §5 增殖机制在
                                    用户使用过程中自动生成
```

> 设计原则：**一级菌域由用户选，其余菌群由生态长出来。**
>
> v0.1 §22：Agent 的结构应该由用户的思想历史逐渐「长出来」，而不是产品经理把 100 个 Agent 写死。首启选择只回答「你从哪里开始思考」；你未来会思考什么，交给增殖（§5）、唤醒（§7.3）与益生菌漂移（04 §5.1）去发现。

首启界面文案要点（详见视觉设计稿）：强调「未选择的领域不会消失，它们沉睡着，等你的想法唤醒」。

# 2. Vitality / 活性

## 2.1 公式

```text
V(agent, t) = clamp(0, 100,
    0.35 × Recency(t)          // 近期性
  + 0.25 × AdoptionRate        // 采纳率
  + 0.20 × CitationScore       // 后续影响
  + 0.10 × FrequencyScore      // 参与频率
  + 0.10 × ProbioticAffinity   // 益生菌亲和
)

其中：

Recency(t) = exp(-Δt / τ),  Δt = t - last_contribution_at,  τ = 30 天
  // 「贡献」而非「调用」的时间衰减（v0.1 §21：调用≠贡献）

AdoptionRate = 近 10 次参与中，产出被采纳(❤️/⭐/↗)的次数 / 10
  // 滑动窗口，衡量贡献质量

CitationScore = clamp(0, 1, log(1 + citations) / log(1 + 20))
  // 产物被后续堆肥引用的次数，对数尺度封顶

FrequencyScore = clamp(0, 1, log(1 + participation_count) / log(1 + 50))

ProbioticAffinity = clamp(0, 1, 近 90 天用户投放相关益生菌次数 / 5)
  // v0.1 §12：反复投放同方向益生菌会缓慢改变菌床
```

## 2.2 设计说明

- **三条通道严格分离**：FrequencyScore（调用频率）、AdoptionRate（贡献价值）、CitationScore（思想后续影响）。这是 v0.1 §21「调用频率 ≠ 贡献价值 ≠ 思想后续影响」的公式化落实。
- 三个信号权重不同：后续影响 (0.20) > 单次采纳 (0.25 合并权重最高体现质量优先)。**一个三个月前的洞察若持续被引用，其来源 Agent 仍保持高活性**——CitationScore 不随 Δt 衰减。
- 权重与 τ 均为初始值，后续按 §10 的实验框架调整。

## 2.3 营养缓冲（Nutrition Buffer）

Vitality 是慢变量；营养是快变量。堆肥结束时的营养先进入快速衰减的缓冲区：

```text
V_effective = V + nutrition_buffer,  封顶 100
nutrition_buffer ← nutrition_buffer × exp(-Δt / 14天) + 本场新增营养
```

> 长期积累路径（v0.1 §19）：
> 贡献 → 营养（快）→ 活性（慢，通过 AdoptionRate/CitationScore 沉淀）→ 更多参与机会 → 更多贡献。
> 营养是短期激励，采纳与引用的沉淀才是长期活性的来源。

# 3. 营养机制 / Nutrition

## 3.1 评分流程

堆肥完成后，思想园丁执行一次轻量评估（单次廉价模型调用，输入为结构化 stage 记录）：

```text
对每个参与 Agent a：
  1. 其输出观点被最终产物引用的段落比例        → base 0-4 分
  2. 其贡献进入 adopted 洞察的命题数            → +1/条，封顶 +3
  3. 用户后续在相关段落点的 ❤️⭐↗              → 事件到达时追加（延迟营养）
  4. 阶段 4 反驳阶段被其他 Agent 有效回应的次数  → 反驳菌专属通道 +0.5/次

nutrition_awarded[a] = 总分（典型范围 0-10）
```

## 3.2 反馈→营养映射

| 用户行为 | 即时营养 | 说明 |
| --- | --- | --- |
| ❤️ 有启发 | 相关段落 Agent +1.5 | |
| ⭐ 值得保留 | +3 | 同时 Insight.importance +10 |
| ↗ 继续发展 | +3.5 | 同时生成后续堆肥候选 |
| 修改产物 | 主要贡献 Agent +4 | diff 是最强的质量信号 |
| ? 我不同意 | 0（不惩罚） | Insight → contested；标记分歧方向供园丁下次引入对立菌 |
| 引用（后续堆肥命中） | 溯源 Agent +2 | 见 §7 后见之明 |

> **不惩罚原则**：异议不扣营养。防止 Agent 学会只说用户爱听的话——生态需要安全的反对者。

## 3.3 评估的防作弊约束

园丁评估 Prompt 中强制：营养评分必须给出**引用证据**（引用产物中哪一段来自哪个 Agent 的哪个观点），无证据不得给分。评估结果写入 `nutrition_awarded` 供用户在产物「🧠 本次堆肥使用的菌群」一节查看（透明性）。

# 4. 激活与召集 / Activation

## 4.1 激活权重

每次堆肥，园丁为候选池中每个 Agent 计算：

```text
w(a) = relevance(a | crumbs, probiotics) × f(V_effective(a))

f(V) = 0.3 + 0.7 × V / 100
  // 低活性只降权、不排除——生态保持开放（防止强者恒强的马太效应过度）
```

`relevance` 由两个信号合成：面包渣 embedding 与 Agent capability_card + specialties 的相似度；益生菌 domain_boosts 倍率。

## 4.2 异质性配额（70 / 20 / 10）

**茧房防线是算法性的，不是提示词性的。**不依赖 LLM 的自觉，在代码层强制执行（v0.1 §35）：

```text
每场堆肥召集 4-7 个 Agent：
  70%（≥3 个）  来自 w(a) 排序的头部 —— 当前相关菌
  20%（≥1 个）  来自排序中段的相关邻域 —— 相邻领域菌
  10%（≥1 个）  从低相关但未休眠的池中随机抽取 —— 意外菌

补充规则：
  + 跨学科益生菌在场时 → 配比调整为 50/30/20
  + ε-greedy：10% 概率额外加入一个 embryo 状态的新生菌（探索）
  + 反驳菌保证条款：无论如何组成，阶段 4 必须有一个方法菌在场
    （若无则强制空降，见 05 输出协议 §4 强制魔鬼代言人）
```

激活结果记入 `gardener_plan`（含每个 Agent 的 w 值与配额角色），保证整场可审计、可回放。

# 5. 增殖 / Proliferation

## 5.1 触发条件（全部满足）

```text
① 该 Agent 在某子方向（由 Topic 聚类标记）参与 ≥ 8 次堆肥
② 在该子方向产出 adopted 洞察 ≥ 3 条
③ 该子方向的采纳率 > 全体均值
④ 活跃 Agent 总数 < 24（生态容量上限，控成本与上下文预算）
```

## 5.2 动作

```text
1. 生成子代 Agent（status = embryo）：
   capability_card = 父卡 + 子方向聚焦 + 从其最佳贡献中蒸馏的 2-3 个范例
   specialties = [子方向]
2. 父代保留，转移 10 点 Vitality 给子代（生态繁殖成本）
3. 写入 bed_event: agent_spawned {parent, child, direction}
4. 在下次产物「🧠 菌群」一节向用户宣告：「算法社会学菌 从 社会学菌 增殖出来了」
```

> 增殖不是静默的数据库操作——**生态变化必须让用户看见**，这是「观察思想如何生长」产品体验的一部分。

# 6. 融合 / Fusion

## 6.1 触发条件

两个 Agent 在 ≥ 6 次堆肥中共同参与，且共同产出（同一 Insight 的 source_agents 同时含二者）≥ 2 条 adopted 洞察。

## 6.2 动作（v0.1 需用户确认）

```text
1. 系统生成融合提案卡片：
   「算法社会学菌 + 认知科学菌 长期共同工作，
    是否融合为新的 算法认知生态菌？」
   （含两者近年共同产出的最佳 3 条洞察作为「共生证据」）
2. 用户确认 → fused Agent 诞生：
   capability_card = LLM 合成两者的能力卡（保留双方思考准则的并集）
   Vitality = 两者均值，nutrition_buffer = 两者之和 × 0.5
   fusion_of = [a, b]，contribution_history 合并链接
   源头两者 → dormant（压缩保留，可唤醒）
3. 用户拒绝 → 融合冷却 30 天内不再提案
```

> 融合是重大生态事件（不可逆地改变菌群结构），必须用户确认。增殖是自然生长，静默发生 + 事后宣告；融合是生态重组，事前确认。**粒度差异是有意的。**

# 7. 压缩与休眠 / Compression & Dormancy

## 7.1 阈值

```text
连续 90 天无贡献 且 V < 15
  → 进入压缩候选，在产物尾部向用户提示（用户可一键保活）

V < 8 或 连续 180 天无贡献
  → 自动压缩休眠（写 bed_event，产物尾部周报可见）
```

## 7.2 压缩形态

```text
活跃态（常驻激活池）
  capability_card 全文（300-600 token）
  + specialties + 近期贡献索引

休眠态（压缩卡 ≈150-250 token）
  ┌────────────────────────────────┐
  │ 博物馆学菌 · Dormant            │
  │ 核心能力：博物馆叙事/展陈逻辑/  │
  │ 观众研究/文化机构制度           │
  │ 历史贡献：参与 7 次堆肥，       │
  │ 产生 3 条长期保留洞察           │
  │ 唤醒暗号：博物馆、展览、策展    │
  └────────────────────────────────┘

full_profile 与 contribution_history 永久保留（INV-7 休眠优于删除）
```

压缩卡是**激活池的索引表示**：园丁扫描全部压缩卡的成本 ≈ 24 × 200 = 5K token 以内，可每次全量注入。

## 7.3 唤醒 / Awakening

```text
唤醒触发（任一）：
  ① 面包渣 embedding 与某休眠菌压缩卡「唤醒暗号」强匹配
  ② 用户投放点名其领域的益生菌
  ③ 休眠菌的旧洞察被新堆肥引用 ≥ 2 次（后见之明信号）

唤醒动作：
  full_profile 恢复 → status = embryo（V = 20，需重新挣回地位）
  写 bed_event: agent_awakened
```

## 7.4 后见之明 / Hindsight Credit

> v0.1 §21 的关键场景：一个 Agent 三个月前产生的洞察如果之后不断被引用，它仍应保持生态价值。

实现：`insight.cited` 事件永远追溯其 `source_agents` 发放营养（+2/次），无论 Agent 当前状态。休眠菌收到 ≥ 2 次引用进入唤醒候选。**引用是唯一能穿透休眠状态的信号。**

# 8. 生态健康指标

定期（夜间任务）物化到 Bed：

| 指标 | 定义 | 阈值动作 |
| --- | --- | --- |
| 多样性指数 | 近 30 天参与堆肥的不同领域菌数量 | < 3 → 提高意外菌配比至 20% |
| 回声风险 | 近 10 场采纳洞察集中于同一领域菌的比例 | > 60% → 强制未来 3 场各引入 1 个对立领域菌 |
| 扰动审计 | perturbation_log 中意外菌实际入场率 | < 10% → 报警（配额执行有 bug） |
| 新生菌存活率 | embryo → active 的转化率 | < 30% → 降低增殖阈值或提高探索 ε |

# 10. 参数表与实验框架

| 参数 | 初始值 | 调整依据 |
| --- | --- | --- |
| τ（Recency 半衰期） | 30 天 | 用户兴趣迁徙周期观察 |

# 11. 本文关键决策汇总

| # | 决策 | 理由 |
| --- | --- | --- |
| D9 | Vitality 五因子公式，三通道分离 | 公式化「调用≠贡献≠影响」 |
| D10 | 营养走快速衰减缓冲区，不直接改 Vitality | 慢变量防抖，短期激励即时可见 |
| D11 | 异质性配额在代码层强制，不靠 Prompt | 茧房防线必须算法性 |
| D12 | 低活性只降权不排除 | 防马太效应锁死生态 |
| D13 | 异议不惩罚 | 防谄媚循环 |
| D14 | 增殖静默+事后宣告；融合事前确认 | 生长 vs 重组的粒度差异 |
| D15 | 压缩卡=激活索引，全档永存 | 唤醒无损；扫描成本可控 |
| D16 | 引用信号穿透休眠 | 后见之明归因 |
| D53 | 首启菌域 7 选 N（通用学科），未选者休眠，其余增殖生成 | 一级菌域用户定，菌群结构生态长 |
