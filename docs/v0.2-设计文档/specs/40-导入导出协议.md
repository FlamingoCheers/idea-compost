# 40 · 导入导出协议 / Backup & Restore Protocol

> v0.2 实施规格 · 对应用户需求：「所有产物（产物、Agent 菌群等）和面包渣都能一键导出为压缩包；换设备导入压缩包即可恢复整个状态」

------

# 1. 目标

```text
导出：一台设备 → 一个 zip → 完整认知生态
导入：一个 zip → 任何设备 → 完整恢复，数据无缝同步
```

覆盖内容（8 张表 + 2 份配置，即全部用户数据）：

| 包内文件 | 内容 | 对应表/存储 |
| --- | --- | --- |
| manifest.json | 格式版本、App 标识、导出时间、DB 版本 | — |
| profile.json | 昵称、头像 emoji | SharedPreferences(profile) |
| provider.json | AI 服务商配置（含 API Key） | EncryptedSharedPreferences |
| ideas.json | 全部思想面包渣 | ideas |
| composts.json | 全部堆肥记录（含产物 JSON、营养结算、roster） | composts |
| stages.json | 全部阶段快照（checkpoint） | compost_stages |
| feedbacks.json | 全部用户反馈事件 | feedback_events |
| agents.json | 全部 Agent 菌群（含能力卡/活性/休眠压缩卡/融合与增殖谱系） | agents |
| probiotics.json | 全部益生菌（含已隐藏的内置菌） | probiotics |
| bed_events.json | 全部生态事件（append-only 审计链） | bed_events |
| llm_calls.json | 全部调用遥测 | llm_calls |

> 设计原则（37 Local-first）：**用户的思想首先属于用户**。导出是全量、无损、开放格式（zip + JSON），不锁定在任何专有数据库格式中。

------

# 2. 导出流程

```text
设置 → 🗄 思想备份 → ⬆ 导出备份
  → SAF CreateDocument（建议文件名：思想堆肥备份-YYYYMMDD-HHmm.zip）
  → BackupManager.exportTo(uri)（IO 线程）
  → 全表读取 → JSON 序列化 → java.util.zip 打包 → 写入 Uri
  → Snackbar 汇报：N 颗面包渣 · N 次堆肥 · N 位菌群 · N 枚益生菌
```

------

# 3. 导入流程

```text
设置 → 🗄 思想备份 → ⬇ 导入备份
  → SAF OpenDocument（application/zip）
  → 确认对话框：「导入会清空这台设备上的全部思想数据……不可撤销」
  → BackupManager.importFrom(uri)（IO 线程）
  → 校验 manifest（app=ideacompost；format_version ≤ 当前）
  → 单 Room 事务内：8 表 deleteAll + 全量 insertAll
  → 恢复 profile 与 provider（UI 状态同步刷新）
  → Snackbar 汇报恢复统计
```

## 3.1 校验与失败语义

```text
缺 manifest.json            → 拒绝：「不是有效的思想堆肥备份」
app ≠ ideacompost           → 拒绝
format_version > 当前       → 拒绝：「备份来自更新版本，请先升级 App」
format_version < 当前       → 接受（向后兼容；缺文件按空表恢复）
任何解析异常                 → 事务回滚，本机数据不受影响（失败不落库）
```

## 3.2 主键与自增

- 业务主键（ideas/agents/probiotics/composts 的 id）原样保留——菌群谱系（parent_id / fusion_of）、面包渣引用（input_idea_ids）、溯源关系全部不断链。
- 自增主键（stages/feedbacks/bed_events/llm_calls 的 id/seq）不导出，导入后由 SQLite 重新分配——事件顺序由 created_at/ts 字段保证。

------

# 4. 安全说明

- 备份包含 AI 配置（含 API Key）——这是「换设备完整恢复」需求的一部分。导出文件请用户自行妥善保管（系统设置页有提示文案）。
- 若用户不希望备份 Key：导入前可手工从 zip 删除 provider.json（缺失时按未配置处理）。

------

# 5. 实现锚点

```text
data/backup/BackupManager.kt          导出/导入/校验/JSON 映射（单文件全量）
data/db/dao/*.kt                      各 DAO 的 all()/insertAll()/deleteAll()（specs/40 注释）
ui/settings/SettingsScreen.kt         BackupSection + SAF launcher + 导入确认对话框
ui/settings/SettingsViewModel.kt      exportBackup()/importBackup()（backupBusy 防重入）
```
