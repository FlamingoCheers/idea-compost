# 41 · 并行堆肥协议 / Parallel Composting

> v0.3 · 对应工作计划 V1/V1b
>
> S3 发酵阶段同一轮内的 Agent 调用相互独立（各自输入 = 面包渣 + 益生菌 + 之前轮次记录，见不到同轮伙伴），因此同轮并行是纯实现层优化，不改生态协议（02）与园丁调度协议（03）的任何语义。

## 1. 并发模型

```text
每轮发酵：
  val sem = Semaphore(4)                 // 默认并发度 4（参数表可调）
  roster.map { agent -> async {
    sem.withPermit {
      retryWithBackoff(times = 2) {      // 失败重试 2 次，指数退避 + 抖动
        llm.complete(card(agent), ...)
      }.onSuccess { stage -> dao.insertStage(stage) }   // 完成一个落库一条
       .onFailure { dao.insertStage(error 记录) }        // 两次重试仍失败 → 跳过该菌
    }
  }}.awaitAll()
  transcript = 按 roster 名单顺序（非完成顺序）拼装   // 保证下一轮 prompt 稳定可回放
```

## 2. 规则

| # | 规则 | 理由 |
|---|------|------|
| P1 | 只并行同轮调用；轮间、S1/S2/S4/S5 保持串行 | 轮次有数据依赖；流水线节点是单调用 |
| P2 | 并发度默认 4，集中配置 | 供应商限流；429 在 M3 已实测出现 |
| P3 | 失败重试 2 次（退避 + 抖动）后跳过，不整轮失败 | 发酵容错优先；缺席菌只是本轮少一个声音 |
| P4 | error stage 照常落库（stageKey 同、ok=0） | 遥测与断点续跑（重启只补跑缺失的调用） |
| P5 | transcript 按名单顺序拼装，与完成顺序解耦 | 同一现场可回放；下一轮输入稳定 |
| P6 | 等待页进度细化到「第 n 轮 x/y 菌」 | 每个调用完成都可实时上报 |

## 3. 边界与未来

- **同轮辩论**（Agent 可见同轮伙伴发言后再反驳）若将来引入，属新的阶段类型，天然串行，不套用本协议。
- 参数：`parallelism=4`、`retries=2` 入 §10 参数表（02），随配置文件下发，不硬编码。

## 4. 实现与验证记录（v0.3）

- 实现：CompostEngine.kt S3（Semaphore(PARALLELISM=4) + 300ms 错峰 + RETRIES=2 退避重试 + 缺席标记落库）；CompostProgressBus（逐菌进度）；CompostService（前台服务，熄屏续跑，通知随进度更新）。
- 验证（fake OpenAI + adb reverse，2026-08-29）：并发重叠与 4 上限补位 ✓；6×500 后第 3 次引擎尝试成功 ✓；9×500 耗尽后跳过、轮次完成 ✓；熄屏 12s 持续发酵 ✓；等待页「第 n 轮 · x/y 菌已归位」✓。全程记录见 docs/质量/BUGFIX-LOG.md v0.3 节（BUG-016/017/018）。
