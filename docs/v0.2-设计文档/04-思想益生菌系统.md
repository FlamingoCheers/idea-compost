# 04 · 思想益生菌系统 / Probiotic System

> v0.2 设计文档集 · 对应 v0.1「下一阶段设计重点」第 4 项
>
> 定义：Probiotic Ontology、内置菌种、用户自定义菌种、菌种组合、菌种对 Agent 权重的影响。
>
> 定位（v0.1 §11.1）：益生菌不是 Prompt Template，是**用户主动施加给本次堆肥的认知方向与选择压力**。

------

# 1. Probiotic Ontology

```text
Probiotic
├── id
├── name                // 「哲学益生菌」
├── description         // 一句话说明，用户选择时看
├── prompt_logic        // 注入园丁与菌群调度指令的思考要求（自然语言）
├── scope               // global_builtin | user_defined
├── domain_boosts       // {媒介研究菌: 2.0, 社会学菌: 1.5, 文学菌: 1.2}
├── stage_emphasis      // 对发酵轮次的侧重，如 {conflict: +1轮}
├── diversity_shift     // 配额偏移，如 跨学科菌 → 50/30/20
├── usage_count         // 使用次数（驱动 ProbioticAffinity）
├── created_at / updated_at
└── user_feedback_stats // ❤️? 统计
```

三个结构化字段（domain_boosts / stage_emphasis / diversity_shift）是益生菌「生态干预」能力的实现——它改变的不只是措辞，而是**菌群组成与流程形态**。这是益生菌区别于普通 Prompt Template 的本体论差异（v0.1 §11.1）。

------

# 2. 内置菌种（v0.1 §11.2 全部实现）

| 菌种 | prompt_logic 核心 | domain_boosts | diversity_shift |
| --- | --- | --- | --- |
| 哲学益生菌 | 从存在、自由、意义、异化等角度重新审视问题 | 哲学菌 ×2.5 | — |
| 科研益生菌 | 将直觉转化为研究问题，识别研究边界与空白 | 研究问题菌 ×2.5，假说菌 ×1.5 | — |
| 反直觉益生菌 | 不接受默认前提，寻找最违反直觉的解释 | 反事实菌 ×2，概念辨析菌 ×1.5 | 意外菌配额 10%→20% |
| 魔鬼代言人益生菌 | 假设用户核心判断是错的，为反方构建最强论证 | 反驳菌 ×3 | — |
| 跨学科益生菌 | 从多个看似无关学科寻找结构相似性 | 类比菌 ×2 | **50/30/20** |
| 苏格拉底益生菌 | 不急于回答，不断追问判断成立的前提 | 概念辨析菌 ×2.5，哲学菌 ×1.5 | — |

内置菌种为 global_builtin，不可删除、可隐藏。

# 3. 用户自定义菌种

创建流程（低阻力原则同样适用）：

```text
用户输入一句话方向（如「这次我想从文学角度看」）
  → 系统生成菌种卡草稿（name/description/prompt_logic/三个结构化字段）
  → 用户可改可确认（默认直接确认，零必填项）
  → scope=user_defined 入库
```

约束：

- 每用户自定义菌种 ≤ 20 个（超出提示合并相似菌种）
- 自定义菌种不写死 domain_boosts 数值——由「方向语句 + 目标菌群 embedding 匹配」动态计算，避免用户手工调参
- 隐私：自定义菌种属用户数据，仅本地 + 私有云同步，不进入全局模板库

------

# 4. 菌种组合

- 每次堆肥 ≤ 2 个益生菌（03 协议预检硬约束）
- 组合语义为**叠加**：domain_boosts 取乘积、diversity_shift 取更激进值、prompt_logic 拼接
- 冲突检测：魔鬼代言人 + 苏格拉底同时使用会稀释焦点（一个攻结论、一个攻前提）→ 界面提示但不阻止
- 典型组合示例：`哲学 + 跨学科`（结构与视野）、`科研 + 反直觉`（突破性假设）

------

# 5. 益生菌对 Agent 权重的影响（与 02/03 协议的接口）

```text
w(a) = relevance(a | crumbs, probiotics) × f(V_effective(a))
                ↑
   domain_boosts 在此生效：relevance = sim(crumbs, a) × boost(probiotics, a)

流程影响：
  stage_emphasis  → 03 §6.1 轮次展开（如魔鬼代言人 → 深模式的独立反方轮）
  diversity_shift → 03 §5 召集配额覆盖（70/20/10 → 50/30/20）
```

## 5.1 一次性干预 vs 菌床漂移（v0.1 §12 落实）

```text
单次使用：只影响本场堆肥（selection pressure）
反复使用：usage_count 累积
  → 相关 Agent 的 ProbioticAffinity 因子上升（Vitality 五因子之一）
  → 长期反复投放同方向益生菌 = 菌床缓慢漂移
例：用户连续 5 次投放文学益生菌
  → 文学菌/叙事菌/象征菌 V 上升 → 更容易被自动召集
  → 但受异质性配额保护，不会挤占相关性菌的基本盘
```

> 益生菌是压力，菌床是选择的结果。用户用脚投票的方向最终长进生态，这正是「生态干预」隐喻的机制化。

# 6. 益生菌自身的反馈回路

- 堆肥产物尾部显示本场使用的益生菌及其效果简评（园丁阶段 5 顺带生成，≤2 句）
- 用户可对益生菌本身 ❤️/?；? 率高的自定义菌种在创建类似菌种时提示参考历史反馈
- 内置菌种使用率是产品层面的观测指标：某内置菌种使用率 < 1% 时 review 其描述文案（通常是可发现性问题，不是机制问题）
