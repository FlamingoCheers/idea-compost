# 2. 两项调研的答案（摘要）

**Q1：记忆管理系统能不能直接抄 OpenCode ACP 插件？**
不能直接抄代码（TS 插件、编码对话域、栈不匹配），但其架构思想全部吸收：三层 LSM 蒸馏（T1 堆肥中间产物 → T2 主题卡 → T3 菌床快照）、摘要即历史元数据、先搜索后解压、用户资产永不压缩。结合 Letta 的 sleep-time compute 形成本 APP 的热/温/冷三层记忆架构与夜间后台任务（06 文档，D37–D41）。

**Q2：底层要不要抄一个多 Agent 协作框架？抄哪个？**
都不抄。核心洞察：Agent 菌群的增殖/融合/休眠/活性在任何框架里都不存在——生态本来就是应用侧数据逻辑；框架能给的只是多步编排，而我们的流程是静态五阶段、状态本就落库。v0.2.1 后更进一步：编排层就是 App 内一个 Kotlin 协程模块（≈500 行），纯本地运行，连服务端都不需要（07 文档，D42–D46、D54）。

# 7. v0.2.3 实装修订（M4：夜间生态任务）

实现「确保这些功能要完全实现」：Agent 生态从静态数据变为运行时系统（domain/EcoEngine.kt，commit 7df1b79）。

## 7.1 夜间生态任务（EcoEngine.runNightly）

设置页（个人页）提供 🌙 按钮，手动触发一次生态任务（v0.1 §21 的时间衰减在真机上无法依赖后台定时器，改为显式按钮 + 未来可加 WorkManager 自动化）：

```text
① 活性重算（对全部菌执行）
   V = 100 × (0.45×exp(-d/30) + 0.30×min(buffer/30, 1) + 0.25×ln(1+pc)/ln(21))
   d = 距 max(last_contribution_at, created_at) 的天数（对应 02 §6 活性公式）
   ΔV ≥ 1 才落库（减少无谓写入）
② 状态机（自动执行，无需确认）
   active  & V<15 & d>90 天  → compressed（压缩为索引卡，card_version+1）
   compressed & d>180 天     → dormant
   dormant/compressed & 近14天面包渣关键词命中 ≥2 条 → active（唤醒）
③ 增殖建议（建议制，需用户确认——借鉴 Anthropic Dreaming "只建议、人决定"）
   active & participation_count≥5 & V≥60 的菌（至多2个）→ LLM 起草子菌
   → 用户在夜报卡片上 ✓采纳 / ✗忽略
④ 融合建议（同上）
   共现矩阵（从堆肥 roster 统计菌对共现次数）中 ≥4 次且双方 active 的最强菌对
   → LLM 起草复合菌 → 用户确认
⑤ 写 eco_task_run 事件 {agents_scanned, auto_actions, suggestions}
```

每次状态变换写 bed_events（agent_status_compressed / dormant / awakened / agent_proliferated / agent_fused，payload 含 before/after/vitality/confirmed_by）——对应「版本化一切」原则。

## 7.2 实测验证结果（模拟器 + SQL 手术加速老化）

- 压缩 ✓：200 天/100 天无贡献的方法菌被压缩（V 0.057 / 1.6）
- 休眠 ✓：compressed 超 180 天 → dormant（seq23）
- 唤醒 ✓：dormant 文学菌被 2 条含「文学」的面包渣唤醒（seq22）
- 增殖 ✓：刷高参与度（pc=6）后夜间任务产出 LLM 建议，采纳后生成子菌（embryo, V=45, parent 关联，seq30 confirmed_by=user）

## 7.3 修正记录

- **D58（唤醒阈值语义）**：awakenByKeywords 原实现统计「命中关键词种类数≥2」，种子领域菌 specialties 为空时只有词干 1 个关键词，永不满足 → 永远无法唤醒。修正为「命中面包渣条数≥2」（每条渣对某菌最多计 1 次）。
- **D59（个人页）**：设置页升级为「个人页」——顶部个人区块（emoji 头像 8 选循环 + 昵称编辑，ProfileStore SharedPreferences）、菌床生态区（活力条 Top8 + 夜间任务按钮 + 夜报 + 建议卡）、❤️捐赠区（收款码占位）、原 AI 服务商/演示模式/调用遥测保留。首页顶栏头像显示 ProfileStore 的 emoji。

- 夜间任务的 WorkManager 自动化（真·夜间）待做；当前为手动按钮
