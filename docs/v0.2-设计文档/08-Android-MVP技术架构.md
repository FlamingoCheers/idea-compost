# 08 · Android MVP 技术架构

> v0.2 设计文档集 · 对应 v0.1「下一阶段设计重点」第 6 项：Markdown 编辑器、本地数据库、卡片渲染、CSS Theme、AI API、后台任务、通知、数据导出。
>
> 架构总纲（v0.2.1 修订）：**纯本地 Agent APP + 云端纯推理**。Agent 集群与 APP 打包，编排/生态/记忆全部跑在设备本地；唯一的外部依赖是 OpenAI 兼容的 AI API。用户的思想首先属于用户，且永远不经过我们的服务器（我们没有服务器）。

------

# 1. 技术栈

```text
语言/UI     Kotlin + Jetpack Compose（Material 3）
架构        单 Activity + Navigation Compose；MVVM + Repository
本地库      Room（SQLite），FTS5 全文检索
本地推理    ONNX Runtime Mobile（embedding 小模型，可选）
Agent 运行时 Kotlin 协程状态机（07 §4.1，≈300 行）+ 模型无关 LLM 客户端
Markdown    编辑：Compose RichText + 自研轻量 MD 渲染（commonmark-java）
后台        WorkManager（夜间任务）
DI          Hilt
网络        OkHttp + Retrofit（仅直连 AI API，OpenAI 兼容协议）
Key 管理    EncryptedSharedPreferences（BYO Key，用户自填）
导出        自研 Canvas 渲染长图
```

不引入任何框架级 Agent/编排依赖（07 D42/D54）；不引入 LLM 厂商 SDK（D46 模型无关）。

------

# 2. 模块划分与信息架构

```text
app
├── input      低阻力输入（首屏：一个问题「今天脑子里有什么面包渣？」）
│              文字/粘贴/图片/分享接收（Share Target，从任意 App 丢进来）
├── crumbs     面包渣库：瀑布流卡片（v0.1 §6 字段）+ 多选进入堆肥
├── compost    堆肥：益生菌选择 → 深度选择 → 进行中(阶段进度) → 产物阅读
├── bed        菌床（v0.1 §4：底层存在，MVP 以「生态周报」卡片形式露出，
│              不做一级入口）
├── export     卡片长图导出（v0.1 §8 三层：内容/渲染/导出）
└── settings   API 配置（供应商/模型/Key，BYO）
```

首屏即输入框（P-01）：无分类、无标签、无文件夹。保存动作 = 按返回键即存草稿级别的零流失。

# 3. 数据层（Room）

九张核心表映射 01 本体论：ideas / composts / probiotics / agents / insights / topics / topic_members / bed_events / feedback_events。

```text
要点：
- Idea.content 存 MD 原文，全文索引用 FTS5（中文分词用 ICU）
- compost_output 存 JSON（真源）+ rendered_md（视图缓存），D5
- bed_events 只追加（append-only），物化快照定期刷新（D4）
- 所有表附 updated_at，同步以 updated_at 为准的 last-write-wins
- 导出：任意面包渣/产物可导出为 .md 文件（INV-10 数据不锁定）
```

# 4. CSS Theme 与卡片渲染

```text
主题包结构（assets/themes/<name>/theme.json + styles.css）：
  五种内置（v0.1 §7）：简约/美式复古/国风复古/多巴胺可爱/手写
  每包含：字体映射（全部开源可分发字体，v0.1 §7 字体原则）
         /配色 token/卡片模板/MD 元素样式

渲染管线：MD → commonmark AST → 主题 CSS 注入 → Compose 富文本
导出管线：同一 AST → Canvas 绘制（头尾含头像/ID/时间/APP 标志，
          可选开关，v0.1 §8）→ PNG 分享

MVP 裁剪：主题固定五选一，不做自定义 CSS（v0.1 允许的未来能力，
接口留好：theme.json 即扩展点）
```

# 5. AI 接入（设备直连，v0.2.1 重写）

```text
模式：BYO Key —— 用户自填供应商地址 + API Key + 模型名
协议：OpenAI 兼容 chat/completions（覆盖绝大多数供应商与中转）
存储：Key 存 EncryptedSharedPreferences，永不上传（也没有我们的服务器）
范围：LLM 调用全部走此通道——园丁/菌群/夜间蒸馏任务共用一个客户端

embedding 方案（按优先级降级）：
  ① 供应商 embedding API（若可用）
  ② 本地 ONNX 小模型（bge-small-zh 级别，~100MB，首次下载）
  ③ 降级 FTS5 全文检索（功能保底，语义检索不可用）

调用纪律（08/03 协议落地）：
  - 单场堆肥预算守卫：≤20 次调用，超限熔断进整合阶段
  - stage 粒度重试：单次调用失败指数退避 ×3，仍败则挂起该 stage
  - 请求超时 120s；无流式需求（Agent 输出为 JSON，整段返回）
```

安全边界：唯一出网流量 = 发给用户配置的 AI API 的 prompt 与返回。面包渣、产物、菌床数据永不离开设备（除用户主动导出）。

# 6. 后台任务与通知

```text
WorkManager 夜间任务（对应 06 §5 sleep-time 清单，约束：充电+WiFi）：
  ① 主题蒸馏（T2 主题卡刷新）          —— LLM（同一直连客户端）
  ② 菌床快照刷新（T3）                 —— LLM
  ③ 休眠巡检（02 §7 阈值）             —— 纯本地计算
  ④ 引用归因结算（后见之明营养）        —— 纯本地计算
  ①② 调用次数少（每周个位数），成本可忽略

通知（克制原则——本产品是思考工具非提醒机器）：
  - 堆肥完成（产物就绪）
  - 生态周报（每周一次：菌床变化、增殖/休眠事件、待发酵的连接建议）
  - 其余一律不打扰
```

# 7. 堆肥进行时：前台保活与等待态 UX 规格（v0.2.1 新增）

堆肥典型耗时 2-6 分钟，且 LLM 调用要求 App 保持运行。这是纯本地架构的核心 UX 代价，必须用体验设计消化掉。

## 7.1 保活策略

```text
① 堆肥进行中保持屏幕常亮（keepScreenOn flag）
② 切后台/锁屏 → status=suspended，正在进行的 stage 调用完成当前 Agent 后暂停
③ 回到前台 → 从最近完成的 stage 恢复（INV-8，Room 即 checkpoint）
④ 不使用前台服务后台偷偷跑：诚实挂起优于不可靠的后台执行，
   且省掉常驻通知栏的打扰
（未来增强：若用户反馈强烈，再评估前台服务方案）
```

## 7.2 等待态界面（「氧气」隐喻）

核心叙事：**堆肥需要氧气，请保持园丁在前台为你工作。**

```text
版式（自上而下）：
  ① 阶段步进条：识别 → 召集菌群 → 发酵 → 整合 → 反哺
     （已完成=苔绿，当前=陶土呼吸态，未到=浅灰）
  ② 中央动画（循环叙事，~2.4s/循环）：
     一把小铲子在土堆上翻动，气泡（氧气）从堆肥中缓缓升起，
     土堆旁一株小芽随节奏轻摆
  ③ 主文案（衬线大字）：「堆肥需要氧气」
     副文案：「请保持园丁在前台为你工作——离开后发酵会轻轻暂停，
              回来时从上次进度继续。」
  ④ 动态旁白（每 ~3s 轮换一条，展示当前菌群在做什么）：
     「反驳菌正在审视『茧房』这个概念的前提……」
     「历史菌在时间纵深里找对照……」
     「园丁在整理菌群们的分歧……」
  ⑤ 元信息：已进行 01:42 · 预计还需 2-3 分钟 · 第 2 轮发酵
  ⑥ 弱化的「暂停」入口（明确告知：暂停无损，进度保留 7 天）

动画设计原则：叙事性优先于信息性——等待页的唯一任务是让
  用户愿意停留（甚至期待），而不是精确汇报进度。
```

# 8. MVP 裁剪清单（v0.1 §39 落实）

```text
不做：知识图谱 / 网页自动管理 / 互联网抓取 / Agent 完全自主创建 /
      社交 / 多人协作 / 游戏化 / 复杂任务管理 / 完整 PKM / 自定义 CSS /
      多设备同步（换机 = 全量导出/导入）/ iOS / 桌面端 / 自有服务器
只验证（v0.1 §40 闭环）：
  丢面包渣 → 选几个 → 选益生菌 → 堆肥 → 读产物 → 反馈 → 菌床变化可见
```

# 9. 里程碑

```text
M1（核心闭环，全本地）：输入/面包渣库/卡片流/编辑器/导出 +
                        首启选菌域（7 选 N）
M2（堆肥管线）：本地 Agent 编排 + AI 直连 + 等待态氧气动画 +
                 产物阅读 + 反馈四键
M3（生态显形）：营养/活性/增殖休眠事件 → 生态周报卡片
M4（记忆分层）：夜间任务 + 主题卡 + 菌床快照注入
```

# 10. 决策汇总

| # | 决策 | 理由 |
| --- | --- | --- |
| D47 | Kotlin + Compose + Room 单技术栈 | 团队维护面最小 |
| D48 | App 零自有服务端，AI 直连（BYO Key + OpenAI 兼容协议） | v0.2.1 纯本地架构；隐私最大化 |
| D49 | 主题包 = JSON + CSS 的资产目录 | v0.1 §7「开放可扩展」接口预留 |
| D50 | MVP 不做多设备同步，换机走导出/导入 | 双向合并是复杂度黑洞，闭环不需要 |
| D51 | 通知只保留两类 | 思考工具非提醒机器 |
| D52 | 生态以「周报卡片」露出而非一级入口 | v0.1 §4：菌床底层存在但不必显式 |
| D53 | 首启菌域 7 选 N，未选者休眠待唤醒 | 见 02 §1；一级菌域用户定，结构生态长 |
| D54 | 纯本地 Agent 运行时（协程编排 + Room checkpoint） | 见 07 §4；省掉整个后端 |
| D55 | AI 直连 + BYO Key + EncryptedSharedPreferences | 无服务器可托管 Key；用户掌控成本 |
| D56 | 等待态：屏幕常亮 + 切后台诚实挂起 + 回前台续跑 | 后台偷跑不可靠且打扰；INV-8 让恢复廉价 |
| D57 | 等待页「氧气」叙事动画（铲子翻堆+气泡+幼芽） | 让用户愿意停留，消化纯本地架构的等待代价 |
