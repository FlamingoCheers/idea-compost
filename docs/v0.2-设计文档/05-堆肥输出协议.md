# 1. 输出结构（v0.1 §29 十节）

产物有**两副面孔**：`compost_output` JSON（真源，供溯源/评估/反哺）与渲染 Markdown（用户视图，D5）。十节与 v0.1 §29 一一对应：

```json
{
  "title": "（初步）劳动的消失与身份的重建",
  "core_ideas": [{
    "text": "核心思想，命题化表述",
    "confidence": "emerging|supported|strong",
    "source_claims": ["S1", "R2", "C1"]
  }],
  "fragment_links": [{
    "from_idea": 3, "to_idea": 7,
    "relation": "碎片3的隐含前提正是碎片7在质疑的东西",
    "source_claims": ["S2"]
  }],
  "forming_judgments": [{
    "text": "正在形成的判断（非结论）",
    "confidence": "...", "source_claims": ["..."]
  }],
  "new_connections": [{
    "text": "与既有洞察/主题的新连接",
    "target": {"type": "insight", "id": 12}, "source_claims": ["..."]
  }],
  "conflicts": [{
    "a": "观点A", "b": "观点B",

  }],
```

# 2. 不确定性表达

置信度三档，措辞规则**强约束**（渲染层根据 confidence 自动改写措辞）：

| confidence | 允许的措辞 | 禁止的措辞 |
| --- | --- | --- |
| emerging（初步） | 「初步看来」「有一种可能是」 | 「显然」「毫无疑问」 |
| supported（较可靠） | 「多个视角支持」「证据倾向于」 | 「证明」「确认」 |
| strong（可靠） | 「有充分理由认为」 | 「真理」「定论」 |

规则：

- confidence 由园丁按 source_claims 的数量与一致性赋予；**单一 Agent 单一来源最高只能 supported**（跨视角交叉才可 strong）
- 产物标题含 confidence 为 emerging 的核心思想时，必须带「（初步）」前缀
- 不消除矛盾：`conflicts` 中的张力在正文中保留原样，园丁不得替用户裁决（P-02）

------

# 3. 反方机制（强制）

```text
产物必须包含 strongest_objection，无例外：
  有反驳菌参与 → 取其最强论证（可多个合并）
  无反驳菌参与 → 园丁以魔鬼代言人身份补位（03 D24）
用户反馈 ?（不同意）→ 该 objection 生成 contested 洞察，
  并提示「下次堆肥引入魔鬼代言人益生菌深挖此分歧」
```

> 没有反方观点的堆肥是失败的堆肥——那是总结，不是发酵。

------

# 4. 新洞察机制

```text
生命周期：
  claim（Agent 主张，带 ID）
    → 命题化进入产物（core_ideas / forming_judgments）
    → status=emerging（堆肥完成，未获用户反馈）
    → 用户 ❤️/⭐/↗ → adopted（入库 Insight，参与菌床）
    → 用户 ? → contested（保留，标记分歧方向）
    → 长期无反馈（30 天）→ archived（不删除，可被引用唤醒）

Insight.importance 初值：
  ⭐ = 60，↗ = 50，❤️ = 40，修改采纳 = 70
  被引用 +10/次，封顶 100
```

`future_directions.as_crumbs` 是闭环设计：产物直接给出「下次可以丢进来的面包渣」，一键转面包渣——把「继续发展」的动作成本降为零。

------

# 5. 来源追踪（三位一体溯源链）

```text
面包渣 Idea ──(被引用)──▶ 主张 claim ──(归属)──▶ Agent
      ▲                        │                     │
      └──────(source_claims)───┴──(source_agents)────┘

正向：任何 Insight 可回溯到「来自哪几个面包渣、哪些 Agent 的哪些主张」
反向：任何面包渣可查看「它参与过哪些堆肥、长出过哪些洞察」
横向：citations 可指向既有 insight（新思想长在旧思想上，营养+2）
```

数据完整性规则：

- 每个 core_idea / judgment / connection 的 `source_claims` 非空且**引用校验通过**（03 §6.2），否则该条目降级为 open_question（无来源的观点不配称为思想）
- 用户视角：产物 MD 的 🍞 与 🧠 两节由 JSON 自动渲染，卡片点开可跳转原面包渣

------

# 6. 渲染与存储

```text
JSON（真源）──render──▶ Markdown（用户视图，十节 emoji 标题）
                │
                └──render──▶ 卡片流预览 / 导出长图（视觉层，v0.1 §8 三层分离）
存储：本地 SQLite + 云端同步；MD 可导出为独立 .md 文件（Local-first，INV-10）
```

# 7. 本文关键决策汇总

| # | 决策 | 理由 |
| --- | --- | --- |
| D31 | 产物双面孔：JSON 真源 + MD 视图 | 溯源/反哺需要结构化，阅读需要散文 |
| D32 | 置信度三档 + 措辞强约束 + 单源封顶 | 保留不确定性是产品哲学（P-02） |
| D33 | 最强反方无条件强制 | 没有反方=总结而非发酵 |
| D34 | 洞察生命周期 emerging→adopted/contested | 用户是采纳最终裁判（P-03） |
| D35 | 溯源链引用校验失败降级为 open_question | 无来源的观点不配称为思想 |
| D36 | future_directions 一键转面包渣 | 「继续发展」动作成本降为零 |
