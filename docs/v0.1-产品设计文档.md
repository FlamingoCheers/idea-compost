# Idea Compost / 思想堆肥 Agent App

## 产品与系统设计文档 v0.1

> **一句话定义**
>
> 一个把人的碎片化思想作为“面包渣”低阻力保存，并通过动态生长的 AI“菌床”对思想进行长期发酵、连接、质疑与深化的个人认知生态系统。

------

# 1. 产品愿景

Idea Compost 不是传统意义上的笔记软件，也不是简单的 AI 第二大脑。

它试图解决的问题不是：

> “我如何更好地整理自己的信息？”

而是：

> **“我如何让那些尚未成熟的思想，在时间中持续生长？”**

人的真实思考往往不是线性的。

一个想法可能今天只是一句话：

> AI 会不会让很多人不再需要工作？

几天之后，它可能与另一个想法产生联系：

> 人为什么需要工作？

再过几个月，用户可能读到社会学、哲学或经济学材料，才突然发现：

> 原来我真正感兴趣的不是“AI 会不会取代工作”，而是“如果劳动不再承担社会分配与身份确认功能，人类社会会发生什么”。

传统笔记软件通常把这些内容当作需要整理的信息。

Idea Compost 则把它们视为：

> **尚未成熟的思想种子。**

因此，产品的核心隐喻不是“数据库”，而是：

> **生态系统。**

------

# 2. 核心隐喻

整个系统由几个相互关联的概念构成：

| 产品概念   | 现实世界隐喻        | 系统含义                                |
| ---------- | ------------------- | --------------------------------------- |
| 思想面包渣 | 落叶 / 有机碎屑     | 用户日常产生的原始思想                  |
| 堆肥       | 发酵过程            | AI 对一批思想进行分析、连接、质疑与深化 |
| 菌床       | 土壤生态            | 用户长期形成的动态认知生态              |
| Agent      | 微生物 / 菌群       | 参与思想处理的不同认知能力              |
| 思想园丁   | 生态管理员          | 管理菌床、选择菌群、调度思考过程        |
| 思想益生菌 | 外部菌种 / 生态干预 | 用户主动指定本次思考方向                |
| 堆肥产物   | 腐殖质 / 新土壤     | 一次思考过程产生的新思想                |
| Agent 休眠 | 菌群休眠            | 长期不活跃的认知能力被压缩保存          |
| Agent 增殖 | 菌群繁殖            | 某一认知方向长期活跃后变得更加复杂      |
| Agent 融合 | 菌群共生            | 经常共同工作的 Agent 形成新的复合能力   |

这一隐喻不是视觉包装，而应该成为整个系统的底层设计原则。

------

# 3. 产品哲学

## 3.1 用户不负责整理思想

产品第一原则：

> **整理是园丁的工作，不是用户的工作。**

用户只需要：

> 想到 → 丢进去。

不要求用户：

- 分类
- 打标签
- 建文件夹
- 建知识图谱
- 决定属于哪个主题
- 决定应该如何组织

这些工作由系统完成。

------

## 3.2 保留思想的“不成熟性”

系统不应该把所有东西都总结成漂亮、完整、确定的观点。

因为很多重要思想最初就是：

- 模糊的
- 矛盾的
- 不完整的
- 甚至可能是错误的

因此系统应该允许并主动保存：

- 尚未形成的直觉
- 相互冲突的判断
- 暂时无法验证的假设
- 用户自己的困惑
- 可能错误的方向

Idea Compost 的目标不是：

> 把混乱变整齐。

而是：

> **把混乱变成能够继续生长的结构。**

------

## 3.3 AI 不应该替用户完成思考

产品应该避免成为：

> “AI 替你思考，然后把答案交给你。”

更理想的关系是：

> AI 帮你看到自己原本没有看到的东西。

因此 AI 的核心职责包括：

- 连接
- 追问
- 反驳
- 提供视角
- 发现结构
- 提出假设
- 暴露未知
- 发现潜在研究问题

而不是简单：

- 总结
- 改写
- 润色
- 代写

------

# 4. 产品信息架构

第一版首页保持极其简单。

```text
首页

├── 🍞 思想面包渣
│
└── 🌱 堆肥
```

未来增加：

```text
├── 🍞 思想面包渣
├── 🌱 堆肥
└── 🪴 菌床
```

但“菌床”是否作为显式一级入口，可以在后续版本根据产品体验决定。

底层始终存在菌床，即使用户看不到它。

------

# 5. 思想面包渣

## 5.1 定义

思想面包渣是用户日常产生的最原始思想单位。

它可以是：

- 一句话
- 一段文字
- 一个问题
- 一个判断
- 一个反应
- 一个灵感
- 一个观察
- 一段引用
- 一张截图
- 一张图片
- 一个尚未完成的念头

------

## 5.2 低阻力输入

这是产品最重要的 UX 原则之一。

用户打开 App 后，不应该首先看到：

> “选择分类。”

而应该看到：

> **“今天脑子里有什么面包渣？”**

输入方式可以包括：

```text
文字
图片
截图
复制粘贴
```

输入之后立即保存。

不要强制用户：

- 命名
- 分类
- 标签
- 归档
- 选择主题

------

## 5.3 Markdown

每一个面包渣本质上都是一个 Markdown 文档。

支持：

- Markdown 编辑
- 实时渲染
- 基础 CSS 样式
- 代码块
- 引用
- 列表
- 图片
- 链接

编辑器设计可以参考 Typora 一类的“所见即所得 / 实时渲染”体验。

CSS 系统应该尽可能采用开放、可扩展的方式，而不是把视觉样式完全写死。

------

# 6. 卡片系统

面包渣和堆肥产物均可以以卡片形式展示。

首页采用：

> **瀑布流卡片布局**

每张卡片显示：

- 标题 / 自动生成标题
- 内容预览
- 创建时间
- 主题提示
- 状态
- 是否参与过堆肥
- 可选的菌床关联

------

# 7. 内置卡片视觉风格

第一版提供五种内置样式：

### ① 简约

- 极简排版
- 大留白
- 强调文字
- 适合作为默认风格

### ② 美式复古

- 复古出版物 / 海报感
- 纸张质感
- 强调粗体标题

### ③ 国风复古

- 东方排版
- 传统色彩
- 书页 / 宣纸 / 古籍感

### ④ 多巴胺可爱

- 明亮
- 活泼
- 圆角
- 趣味装饰

### ⑤ 手写

- 手账感
- 手写字体
- 轻微不规则排版

字体原则：

> **全部使用可合法分发的开源字体。**

未来允许用户：

- 自定义字体
- 自定义 CSS
- 自定义卡片模板

------

# 8. 卡片导出

用户可以将任意思想卡片或堆肥产物：

> 导出为图片卡片。

用途包括：

- 保存
- 分享
- 社交媒体发布
- 个人知识档案

导出视觉与编辑器中的 Markdown 内容分离。导出的长图头尾包括：用户头像、用户 ID、导出时间、卡片创建时间、APP 标志、APP 名称。具体排版可调、显示内容可选。

即：

```text
内容层
Markdown

↓

渲染层
CSS / Theme

↓

导出层
Image Card
```

------

# 9. 堆肥

## 9.1 定义

堆肥不是一个简单的“AI 总结”。

它是：

> **对一组思想进行一次有方向、有生态参与者的思想发酵过程。**

用户可以从思想面包渣（选择的视图中要展示出部分面包渣的文字内容）中：

- 全选
- 多选
- 单选若干卡片

然后：

> **开始堆肥**

------

# 10. 一次堆肥的输入

一次堆肥至少包含三种输入：

```text
① 面包渣
② 思想益生菌
③ 用户长期菌床
```

其中：

### 面包渣

代表：

> 这次我要处理什么？

### 思想益生菌

代表：

> 这次我希望从什么方向刺激它？

### 菌床

代表：

> 我过去长期在思考什么，以及我的认知生态目前是什么状态？

------

# 11. 思想益生菌

## 11.1 定义

思想益生菌不是普通 Prompt Template。

它是：

> **用户主动施加给本次堆肥过程的认知方向与选择压力。**

它可以影响：

- 思考角度
- Agent 选择
- 推理方式
- 输出结构
- 关注重点

------

## 11.2 示例

### 哲学益生菌

要求：

> 从存在、自由、意义、异化等角度重新审视问题。

### 科研益生菌

要求：

> 将直觉转化为研究问题，识别已有研究边界与可能的研究空白。

### 反直觉益生菌

要求：

> 不接受默认前提，寻找最违反直觉的解释。

### 魔鬼代言人益生菌

要求：

> 假设用户的核心判断是错误的，为反方构建最强论证。

### 跨学科益生菌

要求：

> 从多个看似无关的学科寻找结构上的相似性。

### 苏格拉底益生菌

要求：

> 不急于回答，不断追问判断成立所依赖的前提。

------

# 12. 益生菌的本质

益生菌与菌床存在重要区别。

```text
菌床
=
长期生态

益生菌
=
一次性生态干预
```

例如：

用户长期主要思考：

```text
AI
社会
认知
```

某次用户突然说：

> “这次我想从文学角度看。”

那么文学益生菌可以短暂提高：

```text
文学菌活性 ↑↑
叙事菌活性 ↑
象征菌活性 ↑
```

完成本次堆肥后，这种影响不一定永久存在。

但如果用户之后反复进行类似操作：

> 菌床可能逐渐发生变化。

------

# 13. 菌床

## 13.1 定义

菌床是整个产品最核心的隐藏基础设施。

它不是：

> Agent 列表。

也不是：

> 用户知识库。

它是：

> **用户长期认知活动形成的动态生态。**

------

# 14. 菌床记录什么？

菌床至少应该记录：

### 14.1 用户长期关注领域

例如：

```text
AI × 社会
AI × 劳动
算法 × 社会规范
认知科学
博物馆
文学
游戏
```

------

### 14.2 用户经常使用的思维方式

例如：

```text
反事实
机制分析
跨学科类比
概念辨析
历史比较
哲学追问
```

------

### 14.3 用户曾经产生过的重要思想

不是简单存储原文，而是保存：

- 核心命题
- 关联概念
- 来源
- 后续发展
- 是否被用户认可
- 是否再次被引用

------

### 14.4 思想之间的关系

例如：

```text
AI取代劳动
      │
      ├── 人类意义
      │
      ├── 社会身份
      │
      └── 财富分配

算法策展
      │
      ├── 社会规范
      │
      ├── 群体信念
      │
      └── 信息生态
```

------

# 15. Agent 菌群

菌床内部存在动态 Agent 菌群。

Agent 不应该被设计成固定的：

> Agent 1 / Agent 2 / Agent 3

而应该理解为：

> **认知生态中的不同功能菌群。**

------

# 16. Agent 的三大类型

## 16.1 领域菌

回答：

> “从什么知识世界看？”

例如：

- 哲学菌
- 社会学菌
- 心理学菌
- 经济学菌
- 历史菌
- 人类学菌
- 认知科学菌
- 文学菌
- 媒介研究菌

------

## 16.2 方法菌

回答：

> “用什么方式思考？”

例如：

- 反驳菌
- 反事实菌
- 概念辨析菌
- 因果机制菌
- 类比菌
- 历史比较菌
- 证据审查菌
- 系统思维菌

------

## 16.3 创造菌

回答：

> “还能长出什么？”

例如：

- 假说菌
- 概念生成菌
- 研究问题菌
- 世界观菌
- 隐喻菌
- 产品机会菌

------

# 17. Agent 不是固定的

这是系统区别于普通 Agent Cluster 的核心设计。

Agent 有生命周期。

```text
出现
 ↓
激活
 ↓
参与
 ↓
获得贡献
 ↓
活性提高
 ↓
进一步专业化
```

也可能：

```text
长期不参与
 ↓
活性下降
 ↓
压缩
 ↓
休眠
```

------

# 18. Agent 活性

每个 Agent / 菌群拥有一个动态活性值：

> **Vitality**

例如：

```text
哲学菌       92
社会学菌     81
科研菌       73
历史菌       48
文学菌       12
经济学菌      4
```

活性不是简单由调用次数决定。

可以综合：

- 最近参与频率
- 对用户当前主题的相关度
- 产生有效洞察的次数
- 用户是否采纳其产物
- 其产物是否被再次引用
- 是否形成新的长期思想连接
- 用户是否主动投放相关益生菌

------

# 19. Agent 的“营养”

一次堆肥结束之后，系统应该评估：

> 哪些 Agent 对这次思想产生了真正有价值的贡献？

这些 Agent 获得“营养”。

例如：

```text
反驳菌
+8

社会学菌
+6

哲学菌
+4

历史菌
+1
```

长期积累后：

```text
贡献
 ↓
活性
 ↓
更多参与机会
 ↓
更多贡献
```

形成正反馈。

------

# 20. Agent 休眠机制

如果一个 Agent 长时间没有产生有效贡献：

> 不删除。

而是：

> **压缩并休眠。**

例如一个长期不使用的“博物馆学菌”：

原状态：

```text
完整 Agent
+
大量上下文
+
专门 Prompt
+
历史贡献
```

压缩为：

```text
博物馆学菌 · Dormant

核心能力：
- 博物馆叙事
- 展陈逻辑
- 观众研究
- 文化机构制度

历史贡献：
参与 7 次堆肥
产生 3 个长期保留洞察
```

这样既降低系统成本，又保留未来唤醒的可能。

------

# 21. Agent 的时间衰减

可以设置：

> 长期没有贡献的 Agent 活性逐渐下降。

例如：

```text
1个月无有效贡献
→ 活性下降

3个月无有效贡献
→ 进入压缩候选

更长期无贡献
→ Dormant
```

注意：

**“没有调用”不等于“没有贡献”。**

一个 Agent 三个月前产生的一个洞察，如果之后不断被用户引用，它仍然应该保持较高的生态价值。

因此需要区分：

```text
调用频率
贡献价值
思想后续影响
```

------

# 22. Agent 增殖

当某个方向长期活跃时，菌群可以发生细分。

例如最开始只有：

```text
社会学菌
```

后来用户长期研究：

> AI × 社会规范

系统可以逐渐产生：

```text
社会学菌
│
├── 社会规范菌
├── 群体信念菌
└── 算法社会学菌
```

也就是说：

> **Agent 的结构应该由用户的思想历史逐渐“长出来”。**

而不是产品经理一开始把 100 个 Agent 写死。

------

# 23. Agent 融合

长期共同参与相似问题的 Agent，也可以形成复合菌群。

例如：

```text
算法社会学菌
+
认知科学菌
+
媒介研究菌

↓

算法认知生态菌
```

这是一种系统内部的：

> **生态共生。**

------

# 24. 思想园丁

思想园丁是整个 Agent 生态的：

> **Meta-Agent / 元智能调度者。**

它不是单纯“最聪明的 Agent”。

它最重要的职责不是：

> 自己回答问题。

而是：

> **管理菌床，并决定这一次应该让哪些菌参与。**

------

# 25. 思想园丁的核心职责

思想园丁负责：

```text
识别
 ↓
理解
 ↓
召集
 ↓
调度
 ↓
交叉
 ↓
评估
 ↓
沉淀
 ↓
反哺菌床
```

------

# 26. 第一步：识别问题

例如面包渣：

> “我突然觉得信息茧房这个概念可能本身就是错的。”

思想园丁分析：

```text
潜在领域：

算法推荐
媒介研究
社会规范
群体信念
认知偏差

潜在方法：

概念辨析
反事实
反驳
机制分析
```

------

# 27. 第二步：选择菌群

根据：

- 面包渣内容
- 用户长期菌床
- 当前思想益生菌

动态决定 Agent。

例如：

```text
社会学菌      0.80
认知科学菌    0.70
媒介研究菌    0.90
概念菌        0.95
反驳菌        1.00
文学菌        0.10
创业菌        0.00
```

这里的数字可以理解为：

> 本次堆肥的参与权重 / 激活强度。

------

# 28. 第三步：组织多阶段思考

一次堆肥不应该只是：

> 多个 Agent 同时回答 → 主 Agent 总结。

更合理的流程是：

```text
阶段 1：理解
        ↓
阶段 2：拆解
        ↓
阶段 3：连接
        ↓
阶段 4：冲突 / 反驳
        ↓
阶段 5：跨学科重组
        ↓
阶段 6：形成新假设
        ↓
阶段 7：思想园丁整合
```

这样才能产生真正的“发酵”。

------

# 29. 堆肥产物

一次堆肥完成后，产生一个新的 Markdown 笔记。

自动保存至：

```text
🌱 堆肥
```

堆肥产物不是简单总结。

建议固定包含：

```text
# 标题

## 🌱 核心思想

## 🧩 原始碎片之间的联系

## 🌿 正在形成的判断

## 🧬 新产生的连接

## 🔥 可能存在的冲突

## 👿 最强反方观点

## ❓ 尚未解决的问题

## 🌱 可以继续发展的方向

## 🧠 本次堆肥使用的菌群

## 🍞 来源面包渣
```

这样用户可以看到：

> 这个思想是怎么长出来的。

------

# 30. 堆肥反哺菌床

这是整个系统闭环的关键。

```text
面包渣
   ↓
堆肥
   ↓
新思想
   ↓
用户认可 / 修改 / 引用
   ↓
菌床更新
   ↓
Agent 活性变化
   ↓
下一次堆肥
```

因此：

> **堆肥不是输出，而是菌床的一次生态变化。**

------

# 31. 用户反馈也是营养

用户不应该被要求复杂地给 AI 打分。

可以采用低成本反馈：

```text
❤️ 有启发
⭐ 值得保留
↗ 继续发展
? 我不同意
```

这些行为本身就是菌床信号。

例如用户频繁引用某个 Agent 的洞察：

> 说明该 Agent 对用户具有较高价值。

------

# 32. 菌床应该随着用户关注点迁徙

用户的兴趣不是固定的。

例如：

### 第一阶段

```text
AI
↓
生产力
↓
未来工作
```

菌床：

```text
劳动经济学 ↑
社会学 ↑
哲学 ↑
```

半年后：

```text
AI
↓
算法
↓
社会规范
```

菌床自然变成：

```text
社会学 ↑↑
认知科学 ↑↑
媒介研究 ↑
劳动经济学 ↓
```

因此：

> **菌床不是用户人格的静态画像，而是用户近期认知活动的动态生态。**

------

# 33. 菌床不应该过度固化用户

这是一个重要的安全设计原则。

系统不能因为：

> 用户过去经常思考 A

就不断给用户推荐：

> A。

否则菌床最终会变成：

> **AI制造的信息茧房。**

因此思想园丁必须保留：

### 异质性

主动召集：

- 不熟悉的领域
- 用户很少使用的方法
- 反方视角
- 相邻但不同的学科
- 偶然连接

换句话说：

> **一个好的菌床不仅需要营养，也需要偶尔引入陌生菌种。**

------

# 34. 菌床与信息茧房的区别

这是整个产品非常值得坚持的设计理念。

普通算法：

```text
你喜欢什么
 ↓
给你更多什么
 ↓
你更喜欢什么
 ↓
给你更多什么
```

Idea Compost：

```text
你长期关注什么
 ↓
形成优势菌群
 ↓
同时主动引入异质菌
 ↓
产生新的连接
 ↓
改变你的关注结构
```

因此：

> **菌床应该既有记忆，也有生态扰动。**

------

# 35. 思想园丁应该管理这种生态平衡

思想园丁不只是：

> “召集最相关 Agent。”

而应该在以下几者之间平衡：

```text
相关性
新颖性
异质性
连续性
反驳性
```

例如：

```text
70% 当前相关菌
20% 相邻领域菌
10% 意外菌
```

具体比例未来通过实验调整。

------

# 36. AI 系统提示词的基本定位

思想园丁的系统 Prompt 核心身份：

> **你是一名思想园丁。**

不是：

- 秘书
- 搜索助手
- 总结器
- 写作助手

而是：

> 一个帮助用户长期培育思想的认知生态管理者。

核心任务：

1. 理解思想，而非整理文字。
2. 发现连接，而非简单总结。
3. 质疑前提，而非无条件认同。
4. 保留不确定性，而非制造虚假的确定性。
5. 提出新的可能，而非替用户决定结论。
6. 管理菌群，而非自己包办全部推理。
7. 让每次堆肥都能够反哺长期菌床。

------

# 37. 技术架构原则

第一版建议采用：

> **Local-first + AI Cloud**

本地负责：

- Markdown
- 文件
- 卡片
- 编辑
- 基础索引
- 用户数据

云端负责：

- LLM
- Agent 调度
- 深度堆肥
- Embedding
- 复杂推理

核心原则：

> **用户的思想首先属于用户。**

因此应该尽可能：

- 本地保存原始思想
- 支持数据导出
- Markdown 可读
- 避免锁定在专有数据库格式中

# 43. 核心设计原则总结

### Principle 01

**输入必须低阻力。**

用户负责产生思想，不负责整理思想。

### Principle 02

**思想允许不成熟。**

不要强迫每一个念头变成完整观点。

### Principle 03

**AI 的任务是促进思考，而不是替代思考。**

### Principle 04

**Agent 是生态，不是工具箱。**

Agent 会：

- 生长
- 衰退
- 增殖
- 融合
- 休眠
- 被唤醒

### Principle 05

**思想园丁负责生态管理。**

它是 Meta-Agent，而不是万能回答器。

### Principle 06

**思想益生菌是用户主动施加的认知方向。**

它改变一次堆肥的生态，而不是简单修改 Prompt。

### Principle 07

**堆肥会改变菌床。**

每一次思考都会改变未来的思考能力。

### Principle 08

**菌床必须允许变化。**

用户的认知兴趣会迁徙，Agent 生态也应该迁徙。

### Principle 09

**休眠优于删除。**

长期不用的 Agent 被压缩，而不是消失。

### Principle 10

**菌床不能成为信息茧房。**

系统需要主动保留陌生性、反方和跨领域扰动。

------

# 44. 产品最终的核心命题

Idea Compost 最终想做的不是：

> “帮你记住更多东西。”

而是：

> **“帮你让自己的思想有机会长大。”**

传统笔记系统解决：

> 我曾经想过什么？

传统知识管理解决：

> 我知道什么？

AI 第二大脑解决：

> AI 能帮我从已有知识里找到什么？

而 Idea Compost 希望解决：

> **我正在成为怎样的思想者？**
>
> **我过去那些零散的念头，经过时间和不同视角的发酵，最终能够长出什么？**

这构成整个产品的核心哲学。
